# executor/main.py

Модуль:
Исполнитель — работает только внутри тоннеля на роутере,
наружу не смотрит. Единственная задача: безопасно прогнать код ученика
и вернуть результат. Ничего не знает про задания/эталоны — это забота
фронта (webapp/), который живёт на VPS.

Классы:

- `RunRequest(BaseModel)`
  Прогон задания: код ученика (обязан определить solve) + тестовый вход.
  Поля:
  - `code: str`
  - `test_input: object`

- `RunFreeRequest(BaseModel)`
  Свободный прогон: только код, без входа и харнесса.
  Поля:
  - `code: str`

Функции:

- `run(payload: RunRequest)`
  Прогон кода с входом через харнесс (sandbox.run_student_code).

- `run_free(payload: RunFreeRequest)`
  Свободный прогон без харнесса (sandbox.run_free_code).

- `health()`
  Живость исполнителя — для деплоя и мониторинга.

# executor/sandbox.py

Модуль:
Исполнение кода ученика в изолированном процессе.

Это ядро проверки: код ученика никогда не выполняется в процессе веб-сервера.
Он пишется во временный файл, оборачивается в харнесс, который читает вход из
stdin и печатает результат в JSON, и запускается отдельным интерпретатором
python с ограничением по времени, по памяти и с урезанным окружением (чтобы
код ученика не мог прочитать переменные окружения сервера, например токены).

Это слой изоляции на УРОВНЕ ПРОЦЕССА. Сетевая/файловая изоляция живёт на
один уровень выше — в контейнере Docker, в котором крутится сам этот сервис
(read-only rootfs + tmpfs на /tmp + cap_drop ALL + запрещённая исходящая
сеть через iptables DOCKER-USER, см. executor/docker-compose.yml). Таким
образом, даже если код ученика попытается открыть сокет или потрогать диск,
контейнер его остановит. Эфемерности (свежий контейнер на каждый прогон)
пока нет — контейнер переиспользуется, теоретический след в /tmp возможен
(см. docs/decisions.md, осознанный пробел под одного ученика).

Функции:

- `_limit_resources()`
  Лимиты CPU/памяти на процесс кода ученика; вызывается как preexec_fn
  (в дочернем после fork, до exec) — сервер не затрагивается.

- `run_student_code(code: str, test_input) -> dict`
  Ученик обязан определить функцию solve(data). Возвращает
  {"ok": True, "value": ..., "stdout": ...} либо {"ok": False, "error": "...",
  "stdout": ...} — stdout несёт то, что код напечатал сам (до маркера
  результата), нужен «Запустить» с данными на входе (bug.4).

- `run_free_code(code: str) -> dict`
  Свободный запуск без эталона и без ожидания solve(data) — код
  ученика/тьютора выполняется как есть, stdout возвращается как текст.
  Нужен для подсказки, где print('hello') должен просто отработать.
